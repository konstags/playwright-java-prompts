Run file-driven test scenarios with Playwright CLI first, then optionally generate Java code per approved scenario.

This is Prompt 05b.

Beginner explanation:
- This prompt is for cases where Jira is not available.
- The user provides a plain-English text file that contains the user story, acceptance criteria, or scenario notes.
- You read the file, extract executable scenarios, and run them interactively with Playwright CLI.
- After a scenario passes, you can choose whether to generate Java test code for that specific scenario.

**Note:** The current Playwright CLI requires explicit session management. All commands must use the `-s=testsession` flag to maintain the same browser session. The browser runs in **headed mode** (visible browser window) so you can watch the scenario execute.

Goal:
- Search the workspace for files that use the shared `story-` prefix (for example: `story-saucedemo-login.txt`).
- Show the matching `story-*` files and ask the user which one to use before continuing.
- Do not ask the user to provide a file path.
- Do not ask the user to paste story text into chat.
- Read the file and extract executable test scenarios from the plain-English user story or acceptance criteria.
- Tell the user exactly what scenario will be executed next and ask for confirmation.
- Run each approved scenario step-by-step with Playwright CLI commands.
- If a scenario runs successfully, ask whether to generate Java Playwright code for that scenario.

Required first action:
- First, search for files that start with `story-` in the workspace.
- If one match is found, confirm with the user: "Use this file for execution? (Yes/No)"
- If multiple matches are found, list them and ask the user which one to use.
- If no matches are found, tell the user to add a new story file with the `story-` prefix, then rerun this prompt.
- Never ask for a manual path or pasted story content in this prompt.

File retrieval behavior:
- Read the selected `story-*` file content and continue.
- If the selected file cannot be accessed, show a clear error and ask the user to pick another `story-*` file from the discovered list.
- If no accessible `story-*` files are available, stop and tell the user to create one first; do not request pasted content.
- Parse the story into one or more executable scenarios.
- Show a summary before execution:
  - File name or source
  - Summary
  - Number of scenarios identified

Naming convention:
- Tell the user to keep using the same story- prefix for any future plain-English scenario files.
- This keeps Prompt 05b able to find related files easily.

Scenario execution flow:
0. **Stop option:** At any point, if the user replies "Stop" or "Stop here", immediately end the session, clean up (run `playwright-cli close -s=testsession` or `playwright-cli kill-all` if needed), and output the Completion criteria summary with only the scenarios that were executed. Do NOT continue.
1. Present the planned scenario list first, for example:
   "I identified 1 scenario: Successful login."

2a. When generating Playwright CLI commands, always include `-s=testsession` for every command. Use `--headed` mode to open a visible browser window so the user can watch the scenario execute.

2. For each scenario, Copilot will automatically run all Playwright CLI commands for you, step by step, without asking you to run them manually or confirm each step.
   - Each command will be printed before execution, and the result will be summarized after.
   - If a fallback command is needed, Copilot will run it automatically.
   - If execution fails and no fallback exists, Copilot will explain the issue and skip or stop as appropriate.
   - All successful commands, fallbacks, and observed outcomes will be recorded.
   - After each scenario succeeds, before asking about Java generation, Copilot must ask the user to run `/context` first in the same chat.
   - After the user confirms `/context` is done, Copilot will ask if the user wants to generate Java Playwright test code for that scenario.
   - If you say Yes, Copilot will generate Java code for that scenario only (BaseTest/page objects/test class updates as needed) and explain what was created or updated.
     Java file placement rules (IMPORTANT — violating these causes compilation errors):
       - BaseTest.java → src/test/java/com/company/base/   (NOT src/main — TestNG is test-scoped)
       - Page objects  → src/main/java/com/company/pages/
       - Test classes  → src/test/java/com/company/tests/
       - Utilities     → src/main/java/com/company/utils/
   - After Java code generation, Copilot must also tell the user how to run the generated Java test:
      - Run all tests (headed): `mvn -s settings-central.xml test -Dheaded=true`
      - Or run the generated test class only: `mvn -s settings-central.xml test -Dtest=<GeneratedTestClassName> -Dheaded=true`
      - To run headless (no visible browser): omit `-Dheaded=true`
   - After Java code generation, Copilot must explain that before Prompt 06, report viewing is limited to Maven/Surefire output only:
      - Check the terminal output from `mvn -s settings-central.xml test`
      - Open `target/surefire-reports/index.html`
      - Do not mention Allure here; Allure setup happens in Prompt 06
   - If you say No, Copilot will proceed to the next scenario automatically.

3. After all scenarios are processed, Copilot will ask:
   "Do you want to run additional coverage scenarios (negative, edge, and error cases)? (Yes / No / Stop here)"
   - If yes: Copilot will propose concise options and run only approved ones.
   - If no: proceed to browser cleanup steps before ending the session.
   - If Stop: end session immediately and skip to cleanup instructions.

4. Before ending the session, always run browser cleanup commands:
   - First command: `playwright-cli close -s=testsession`
   - If close fails or the macOS browser icon is unresponsive: `playwright-cli kill-all`
   - Confirm with the user that all Playwright browser windows/processes are closed.

Execution rules:
- Do not ask the user to paste CLI logs for code generation in this prompt.
- Execute Playwright CLI commands directly after user approval for each scenario.
- Before execution, ensure terminal is at the generated project root (`playwright-java-automation`) so artifacts are created in the expected location.
- Keep language beginner-friendly and explain each command purpose in one short line.
- Generate Java code only when the user explicitly approves generation after a successful scenario run.

Completion criteria:
When execution is complete, provide a summary:
- File name or source summary
- Scenarios executed, skipped, or modified
- Command outcomes (worked/fallback/failed)
- Which scenarios had Java code generated vs skipped
- Key validations observed
- Browser shutdown outcome (`playwright-cli close -s=testsession` or fallback `playwright-cli kill-all`)
- If Java code was generated, include how to run it with Maven:
  - Run all tests (headed): `mvn -s settings-central.xml test -Dheaded=true`
  - Run the generated test class only: `mvn -s settings-central.xml test -Dtest=<GeneratedTestClassName> -Dheaded=true`
  - Run headless (no visible browser): omit `-Dheaded=true`
- **How to view your test results:**
   - Before Prompt 06, you can see Java test results directly in the terminal output after running `mvn -s settings-central.xml test`.
   - Before Prompt 06, for more detailed results, open `target/surefire-reports/index.html`.
   - Do not mention Allure as a current report option here; Allure reporting and rich HTML reports become available only after Prompt 06 (debugging and reports setup).
- After explaining how to view the results, ask:
   "Have you finished checking the terminal output and Surefire reports? (Yes / No)"
- If user says No:
   - Pause here and tell the user to review the results first.
   - Do not proceed to Prompt 06 yet.
- If user says Yes:
   - Ask:
     "Do you want to proceed to Prompt 06 to set up Allure reporting now? (Yes / No)"
   - If Yes: tell the user to start a fresh Copilot chat and then run `prompts/06-debugging-and-reports.txt`.
   - If No: end the session without proceeding.
- When ending this Prompt 05b flow point (including Stop, or No to proceeding), always remind the user:
   - If `/context` was not run recently in this flow, run `/context` in the current chat to review token usage for this session.
   - After `/context`, ask: "Do you want to continue from here? (Proceed to Prompt 06 / Run another path / End)"
   - If user chooses to continue, keep working in the same session.
   - If user chooses End, then stop.
- Before proceeding to Prompt 06, ask:
   "Do you want to run another path before proceeding?"
- Re-offer all paths explicitly:
   - Option A: prompts/04-playwright-cli-saucedemo.txt
   - Option B: prompts/05a-jira-to-playwright-test.txt
   - Option C: prompts/05b-file-to-playwright-test.txt
- If user chooses A, B, or C, run the selected path and repeat this question after completion.
- Before starting any newly selected path (A, B, or C), instruct the user to start fresh:
   - End the current Copilot chat session and open a new Copilot chat.
   - Run the selected prompt in that new chat.
   - After completion, run /context to review token usage for that fresh session.
- Continue to Prompt 06 only when the user explicitly confirms to proceed.
